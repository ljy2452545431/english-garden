# 登录耗时排查与复测（2026-10-08）

## 原因与改动

原链路为浏览器登录后再取记录，两次请求包含10次串行上游调用。新登录同时返回本人学习状态和版本，两个限流RPC并行、成员与撤销查询并行，成功路径6次上游、4个等待阶段。状态只在授权校验通过后读取；后续接口继续逐次验证身份，不缓存权限。

前端登录请求及旧服务兼容读取共享15秒预算，后端登录下游调用受12秒总信号和8秒单调用信号约束。请求体读取不声称有12秒硬截止。超时/网络失败有中文反馈，不自动重试密码。

## 验收口径

- 指定身份ljy、jfl，顺序低频实测，真实Supabase数据库，现有用户数据；不写改学习记录、不做生产高并发或故障注入。
- 业务成功必须同时满足身份正确、有效版本及完整状态，并与独立真实数据库读取结果一致；退出后令牌必须失效。
- 容量TPS、P95/P99和资源目标未经确认，容量验收为**待验证**，小样本不作容量通过依据。
- 无缓存；无新SQL或迁移，现有user_id过滤查询在真实两账号上验证。

## 原始样本与方法

同一电脑/网络，用Node原生fetch计入响应正文读取。修复前登录+记录两请求合计：ljy 7550ms（3871+3679），jfl 4269ms（2387+1882）。首次观测不等同已确认冷启动。

新后端部署后，合并请求四次：ljy 4613ms、jfl 2930ms、ljy 1512ms、jfl 2633ms。每次业务断言、与真实状态对照、退出失效均通过。首次样本含部署后可能发生的初始化；不把它与后续样本混称稳态P95。

可复跑脚本：`node scripts/login-regression.mjs`；脱敏结果：`login-regression-result.json`。脚本只从本机私密文件读取既有指定账号，不输出密码、令牌或私人正文。账号不存在时不运行。

Chromium手机视口390×844，本地新版前端连接真实已部署后端：点击提交到学习页可见3967ms；1次login POST、0次额外state GET。公网发布版本3be6fdd也已使用同一390×844浏览器视口复测：ljy 7009ms、jfl 3413ms，均正常进入学习页，均为1次login POST、0次额外state GET。该浏览器样本仍有网络波动，不直接与Node样本混合计算。

## 判定

- 功能、真实身份/数据库契约、隔离及退出撤销：通过。
- 调用次数、无自动重试、中文超时、模拟下游失败分类：通过离线契约测试；未在生产注入故障。
- 容量/P95/P99/资源恢复：待验证，无目标和压测环境，不宣称性能达标。
- 真实移动运营商网络与Safari：待设备验证。网络及免费服务初始化会影响耗时，不保证固定秒数。

## 2026-10-10 连接失败排查

用户手机在 Wi-Fi 和移动数据下均提示连接失败。本机真实正式页面使用两账号新密码成功（390×844 Chromium，3922ms / 3432ms），两官方地址 health 均成功；尚未复现用户手机的网络故障，不能断言具体 DNS/TLS/运营商原因。另已修正本机私密账号记录与服务器密码不一致的问题，密码不进入仓库。

登录前新增同项目两条官方线路匿名探测，最多两个 GET，总预算3秒，包含正文读取；选择先完成且业务健康的线路。密码POST只发送一次，探测及登录共用原15秒预算，不自动重试密码。每次明确登录重新探测，避免切换网络后沿用失效线路。所有敏感请求拒绝重定向。自定义本机API保持直连兼容。

备用地址形式见 [Supabase官方示例](https://supabase.com/docs/guides/functions/examples/elevenlabs-transcribe-speech)。不会把账号交给第三方代理。两条域名仍属于同一服务，并非独立容灾服务器，不能保证服务整体故障时可用。

可复跑：设置 `PLAYWRIGHT_MODULE` 为本机 Playwright `index.mjs` 绝对路径，再运行 `node scripts/login-connection-regression.mjs`。默认本机4173预览；`GARDEN_TEST_URL`只允许默认地址和正式站。需已安装Chrome与本机私密账号文件。报告 `login-connection-result.json` 只含脱敏结果，elapsedMs为整个场景耗时（成功场景含退出），不作为纯登录延迟。

- 阻断备用域：主域真实登录通过，密码POST一次。
- 同时阻断两域：明确报错、按钮恢复、脱敏诊断可见，密码POST零次。
